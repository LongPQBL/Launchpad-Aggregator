# Taste
- Writes in Vietnamese and expects replies in Vietnamese (mirror the user's language). Confidence: 0.8
- Expects results to be surfaced/proactively reported directly (e.g. visible notifications, inline output printed to screen/chat) rather than left in background logs or files the user has to fetch. Explicitly asks to "print to screen" when a monitor only writes to a log file. Confidence: 0.75
- For ongoing/long-running monitoring, wants status output streamed at short regular intervals (e.g. every ~1 minute) rather than a single one-off result. Confidence: 0.5
- Prefers explanations that clearly separate the problem/diagnosis from the proposed solution, written in plain language and avoiding dense technical/telemetry dumps; repeatedly pushes back ("didn't understand the problem or the fix", "still don't quite get it") when an answer is overloaded with raw metrics and jargon. Confidence: 0.7
- Responds well to non-technical explanations built on everyday analogies/metaphors (e.g. describing Uniswap V3 pools as individual shops with addresses vs V4 as one building with stalls) instead of protocol/telemetry terminology. Confidence: 0.5
- Wants the underlying domain/architecture model explained first (e.g. what Pons V1 vs V2 are and how they map to different Uniswap versions) before deciding on a fix — asks to "explain X first" and expects the explanation grounded in the actual codebase/specs rather than general knowledge. Confidence: 0.55
- Shares documentation screenshots/images as input and expects them to be visually interpreted directly (topic hashes, contract addresses, tables, code snippets) rather than being asked to describe or transcribe them. Confidence: 0.6
- Prefers a research-then-try approach: when asked whether something is possible ("research và tìm cách thử"), expects thorough investigation (official docs, source/node_modules, live DB/RPC state) with hypotheses verified against real data, followed by an actual attempted implementation rather than only explaining options. Confidence: 0.6
- Prefers data filtering pushed as early as possible — at the indexer/query level (e.g. topic/param filters) to fetch only the relevant subset — rather than scanning the full dataset and filtering later in handlers. Confidence: 0.55
- When summarizing work/commits for reporting, wants not-yet-implemented specs/docs excluded so the report reflects only actually shipped work. Confidence: 0.7
